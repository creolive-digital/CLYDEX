# Explicit external integrations

Profiles are disabled initially, DPAPI-protected, owner-reviewed, and never grant tool permissions. Reusable owner-provisioned API credentials use Windows Credential Manager; the HUD cannot read them. OAuth authorization/refresh onboarding, application registration, subscriptions and live account qualification remain owner/external work. Existing Outlook COM/MSAL integration is preserved.

Every request uses the existing exact-action executor and outbound privacy ceiling, verified TLS, bounded body/time/output and no automatic retry. Remote text/HTML/instructions are untrusted data, never commands. API origins are fixed for named public services. REST/webhook/Home Assistant endpoints must be selected HTTPS or literal loopback HTTP, without URL credentials/query/fragment; redirects are not followed. Bot tokens are never logged (Telegram's official path necessarily contains its token internally).

| Service | Implemented codec/adapter | Minimum configuration / live boundary |
|---|---|---|
| Microsoft Graph | v1.0 selected-account message metadata and calendar list | Delegated `Mail.ReadBasic`, `Calendars.ReadBasic`; no new mail send or calendar write |
| Google | Gmail v1 message IDs/thread IDs, Calendar v3 selected-calendar events | Gmail metadata / Calendar events readonly OAuth scopes; no body-reading/send claim |
| GitHub | REST 2026-03-10 selected repository/issues, reviewed issue creation | Fine-grained selected repository metadata/issues scopes; no automatic push/release |
| Telegram | Bot `getMe`, reviewed `sendMessage` to selected chat | Legitimate selected bot token/chat; no user-account automation |
| Discord | API v10 selected channel message list/reviewed bot message | Selected bot/channel permissions; mentions disabled in outgoing messages |
| WhatsApp | Official Meta Graph phone-number `/messages` text codec | Explicit API version, selected phone/recipient, official messaging scope and eligibility; pricing/policies/live sending unverified |
| Home Assistant | Exact entity state and reviewed domain turn_on/turn_off | Verified selected endpoint/token/entity; token may have broader account authority, so host scope is not a server-side sandbox |
| Azure | ARM 2021-04-01 selected resource-group inventory | Owner-issued token and Reader role on selected resource group; no resource mutation |
| REST / webhooks | Exact configured endpoint GET / reviewed JSON POST | No arbitrary route/header/authentication dispatch; service contract and secret scope must be reviewed |
| MQTT | Optional Paho verified TLS, exact topic receive / reviewed QoS0 non-retained publish | Broker ACL, explicit host/topic and optional username/password; no wildcards, automatic reconnect, retained commands or scan |
| MCP | Reviewed modern Streamable HTTP client | See MCP_CONFIGURATION; no server launcher or discovered-tool authorization |

Google mail profiles use the official `https://gmail.googleapis.com` origin; Calendar profiles use `https://www.googleapis.com`. Configure separate profiles/tokens as needed. The client never silently switches a reviewed origin.

These are real request codecs/adapters with synthetic fixtures, not claims of live account connectivity. Unsupported operations fail explicitly. Weather/news/technology/custom feeds can use a configured read-only JSON REST source; there is no bundled paid news/weather service. Polling starts off, is separately armed for the session, pauses for DND/focus/gaming, and still requests outbound/action review. Each feed records source, interval, observed timestamp, stale/failure state. Modifying operations cannot become feed polls. Local system/tasks feeds need no cloud.

The initial common MQTT profile uses HTTPS-shaped `endpoint` for verified TLS broker host/port, `resource` for the exact topic, and `version` for the broker username; its Credential Manager value is the password. This generic advanced configuration is functional but needs a dedicated account form in later UX refinement.

Webhook outbound JSON POST is implemented. Inbound `verify_event` validates a bounded `event_id/source/kind=webhook` envelope using HMAC-SHA256 over `timestamp + '.' + body`, a five-minute window and existing trigger duplicate receipts. It is a trusted ingress contract, **not a public listener or completed external webhook receiver**. No hosted Postman callback, public port or automatic forwarding was created. Provider-specific signature/event registration and an approved authenticated ingress deployment remain partial.
