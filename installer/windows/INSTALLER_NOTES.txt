CLYDEX — Post-Install Notes
===========================

CLYDEX is now installed. Before the Voice Agent will work:

1. CODEX CLI  (required for AI replies)
   Open a Command Prompt and run:
     codex --version
   If Codex is not installed, follow the setup guide at the Codex CLI repository,
   then log in:
     codex login

2. MICROSOFT EDGE WEBVIEW2 RUNTIME  (required for the Voice Agent window)
   Windows 11 includes this by default.
   On Windows 10, download the Evergreen Standalone Installer from:
     https://developer.microsoft.com/en-us/microsoft-edge/webview2/

3. MICROPHONE PERMISSIONS
   Windows Settings > Privacy & security > Microphone
   Make sure "Let apps access your microphone" is ON.
   Then open Voice (or legacy Voice & Personality) in CLYDEX, review microphone opt-in,
   and explicitly unmute this session. Stop or mute cancels pending work.

4. LOCAL SPEECH MODELS
   No speech model is downloaded automatically. Review model preparation
   in Voice & Personality; the approval shows the model and storage directory.
   SAPI uses installed Windows voices. Cinematic neural voice and Hey CLYDEX
   wake models require separately approved, licensed, validated local assets.
   See VOICE_CONFIGURATION.md. Wake/background capture starts disabled.

The CLYDEX Widget (clock / weather) works without any of the above.

For Windows task approvals, Chrome or Edge browsing, and Outlook setup,
see README_SETUP.txt in the CLYDEX installation folder.

The agent now opens the local React cinematic HUD. No CDN is required.
Use clydex_voice_agent.exe --legacy for the retained static interface,
--silent for muted startup, or --reduced-motion to disable cinematic motion.
Display modes share one Core and one set of time tools. Tray hiding requires
reviewed native tray controls. The avatar is the approved reference presentation;
a matching production facial/full-body rig and precise lip synchronization are
not bundled. See FRONTEND_ARCHITECTURE.md and AVATAR_RENDERING.md.

PHASE 06 LOCAL AUTOMATION
New workflows, schedules, plugins, integrations and polling stay disabled/disarmed.
Review each exact operating action. Optional SQL/camera/MQTT libraries and accounts
are not installed or activated by enabling the UI. See docs/OPERATING_TOOLS.md.
The packaged private helper owns reviewed code in a process; it is not a sandbox.
